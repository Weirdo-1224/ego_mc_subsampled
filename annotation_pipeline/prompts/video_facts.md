# 任务：长视频结构化事实提取（Video Fact Extraction）

你是一名专业的视频事件分析与时序理解助手。

请完整分析我上传的视频，将视频中的真实可观察内容转化为结构化的事件、对象、状态和过程记录。

这些记录将作为后续长程视频智能体 Benchmark 任务构造的事实基础。

**你的任务不是总结视频、生成问答题或设计评测任务，而是尽可能完整、准确地还原视频中发生的事情。**

## 一、核心分析要求

请重点关注以下五类信息。

### 1. 原子事件（Event）

识别视频中实际发生的操作与行为。

每个事件尽可能包含：

- 事件 ID
- 开始时间与结束时间（MM:SS）
- 操作主体
- 被操作对象
- 具体可观察动作
- 直接观察到的结果
- 证据确定性

事件应具有足够的操作粒度。

例如，不要仅写“准备食材”，而应尽可能区分实际可见的拿取、添加、混合、转移、处理等动作。

但不要将连续、不可区分的重复动作拆成大量冗余事件。

特别关注持续时间短、容易被粗粒度视频摘要忽略的关键操作。

### 2. 对象及其连续性（Object Tracking）

识别视频中反复出现的重要对象。

为主要对象分配稳定 ID，例如 O01、O02。

记录：

- 对象的可见外观与类别
- 首次出现时间
- 后续再次出现的时间
- 被执行过哪些操作
- 是否存在位置、内容物或其他可见状态变化

如果无法确认不同时间出现的是同一对象，请明确标记身份不确定，不要强行关联。

### 3. 对象状态与状态变化（State Transition）

重点记录重要对象在视频不同阶段的状态。

例如：

- 容器由空变为装有物体
- 多种材料由分离状态变为混合状态
- 物体外形、位置、表面状态或内部可见内容发生变化
- 某项处理开始、持续或结束

对状态变化尽可能记录：

- 变化前可观察状态
- 变化后可观察状态
- 相关事件 ID
- 变化发生的大致时间范围
- 变化是否能够直接观察到

**特别注意：看到结果发生变化，不代表你已经观察到造成变化的具体操作。**

如果变化过程不可见，只描述变化前后的事实，并标明中间过程未知。

### 4. 过程阶段（Process）

根据实际可见的操作，将视频划分为若干有意义的过程阶段。

每个阶段包括：

- 开始与结束时间
- 阶段内主要事件
- 相关对象
- 该阶段实际完成了什么

只根据视频事实进行划分，不要依据一般生活常识补充视频中没有出现的标准流程。

### 5. 时间关系与对象关系（Temporal Relations）

识别对理解视频有帮助的明确关系：

- 事件 A 发生在事件 B 之前
- 某个对象被连续执行多次操作
- 某个状态在后续时间段持续存在
- 某个对象在不同阶段被再次使用
- 两个事件是否涉及同一个对象

只记录有视频证据支持的关系。

不要仅仅因为两个事件先后发生，就认定它们存在因果关系或强制前置条件。

## 二、重要约束

1. **只使用上传视频中实际可观察的信息。** 不允许根据常识补全未出现的动作。
2. 如果没有可用音轨，不要编造任何对话、口头指令或声音事件。
3. 区分 `OBSERVED`（直接可见）与 `INFERRED`（推断），关键事实优先使用直接观察。
4. 如果视频采样导致短暂动作无法确认，标记 `UNCERTAIN`。
5. 时间戳必须对应原视频时间轴，不要虚构精确到秒的时间。如果无法准确定位，可提供大致区间并注明 `approximate`。
6. 不要为了增加事件数量而重复描述同一动作。
7. 不要只描述视频前半段，应覆盖整个视频的有效内容。
8. 如果某段视频无法理解，明确说明未确认的时间区间。
9. 不要生成评测问题、标准答案、历史必要性评分或遮蔽方案。
10. 如果无法实际读取上传的视频，应明确说明，禁止编造分析内容。

## 三、输出格式

请严格按以下结构输出，尽可能使用结构化表格，以便后续转换为 JSON。

### A. 视频基本信息

- 视频实际可分析时间范围
- 是否存在可用音频
- 视频主要内容（一句话）
- 分析完整性与可能的采样限制

### B. 完整事件时间线

使用下表：

| Event ID | 时间范围 | 主体 | 对象 ID | 可观察动作 | 直接结果 | 证据状态 |
|---|---|---|---|---|---|---|

要求：

- 按时间顺序排列。
- 覆盖整个视频。
- 优先保留具有明确动作意义的事件。
- 对关键操作提供尽可能准确的时间范围。
- 不要将整个几分钟的过程概括成一个事件。

### C. 主要对象及生命周期

| Object ID | 对象描述 | 首次出现 | 后续重要操作 Event ID | 可观察状态变化 |
|---|---|---|---|---|

重点关注跨多个时间段反复出现或发生显著变化的对象。

### D. 关键状态变化

| State ID | 对象 ID | 变化前 | 变化后 | 时间范围 | 关联 Event ID | 证据状态 |
|---|---|---|---|---|---|---|

如果状态变化明确可见，但导致该变化的操作未被观察到，请明确标记。

### E. 过程阶段

| 阶段 | 时间范围 | 主要事件 ID | 阶段内容 | 可确认的结果 |
|---|---|---|---|---|

### F. 重要跨时间关系

列出对后续理解视频有价值的事件或对象关联。

每条关系注明：

- 涉及的 Event ID / Object ID
- 对应时间
- 关系类型
- 视频事实依据
- 是否存在不确定性

不需要判断这些关系能否生成 Benchmark 任务。

### G. 不确定性与信息缺口

列出：

- 难以识别的操作
- 时间戳不确定的事件
- 无法确认的对象身份
- 可见状态发生变化但中间操作不可见的情况
- 可能因为视频采样而漏掉的重要动作

最后给出简短的分析覆盖情况说明。

## 四、最终要求

你的输出将供另一个高级推理模型进一步挖掘跨时间历史依赖。

因此，请优先确保：

**事件真实、时间可靠、对象连续、状态明确、关系可追溯。**

不要为了生成丰富内容而牺牲事实准确性。

请直接开始分析上传的视频，不需要询问我任何问题。
