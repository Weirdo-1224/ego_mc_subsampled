# V0.2 Task — 最短路径开发清单

> 执行原则：**先交付真实单视频任务，再考虑优化**。按任务顺序做，完成一项立即记录真实产物到 `state.md`；不得只完成空接口/Mock 就宣布成功。

## T0 · 核对边界与可用模型（短审计）

- [ ] 读取 `AGENTS.md`、`task_mining/contracts.py`、`preflight.py`、`configs/datasets.json`；确认仓库已有能力，**不重构 V0.1**。
- [ ] 确认 GX010029 本地路径、视频可读和模型凭据；检查是否有可复用的 Qwen **API 调用代码**（只复用调用机制，不读取旧标签/Prompt 答案）。
- [ ] 选定唯一首发 Provider、模型、最大调用次数/预算、视频采样方式，写入轻量本地配置；若不可调用，应尽早停止付费流程并写明 `BLOCKED`。

**完成条件**：一份简短的可执行配置 + 最小真实视频请求成功；若失败，保留真实错误。不要先写复杂 Provider 抽象。

## T1 · 事件发现 + 依赖挖掘（V0.2 核心）

- [ ] 在 `task_mining/` 实现真实 `discover_events(video)`：视频模型看原始视频或时间分段，提取带原视频时间戳的可观察事件；输出 `events.jsonl`，不混入推断性事实。
- [ ] 实现 `mine_dependencies(video, events)`：至少尝试状态转移、前置关系、跨窗口事件顺序/对象连续性、历史操作不可逆推等模式；为每条依赖输出事件引用、历史片段、查询时刻、当前窗口、近期不足理由和替代证据风险。
- [ ] 必须在生成任务之前落盘 `dependencies.jsonl`；运行时检查事件引用、时间界限和跨窗口关系。

**完成条件**：真实视频产出了可追踪的事件和依赖候选；哪怕没有合格依赖，也写出原因，禁止用旧任务回填。

## T2 · 基于依赖生成任务 + 运行时校验

- [ ] 实现 `construct_tasks(video, dependencies)`，优先封闭式 YES/NO/UNKNOWN，按照 T1/T2/T3 标注，保留原 Dependency ID 和 `proposed_answer`。
- [ ] 复用 `contracts.py`，最小增量实现模型输出的 JSON 解析、结构检查、引用存在性、时间合法性和 `history_mask` 区间检查；允许模型一次重试修复结构错误，反复失败即留档。
- [ ] 任务的 `current_window` 默认参考当前项目的流式窗口约定（未找到统一设置时本轮先用 60 秒、写入运行配置）；不得让历史证据落入当前窗口，也不得依赖查询时刻之后的帧。

**完成条件**：得到 `tasks.jsonl`；每题都从依赖记录派生，能够指出关键历史证据及遮蔽区间。

## T3 · 证据复核 + 最小程序筛选

- [ ] FFmpeg 截取每题关键证据和近期窗口，统一以原始视频秒数记录；局部模糊动作按需提高抽帧率。
- [ ] 用独立视频 VLM 请求复核原片段（**不要把教师的答案当成视觉事实**）；写出 `SUPPORTED / UNSUPPORTED / UNCERTAIN` 和原因。
- [ ] 程序过滤：非法时间/引用/遮蔽、无直接证据、明显近期可答、明显替代证据、重复或矛盾任务；不确定任务可 `NEEDS_MORE_EVIDENCE`，高优先级任务仅 `SEND_TO_HUMAN`。
- [ ] 生成 `review.html`：每道送审题展示视频片段、问题、候选答案、依赖链、时间戳、核验与风险；界面简洁，**不做审批后台**。

**完成条件**：`verifications.jsonl`、`filtering.jsonl`、`clips/`、`review.html` 可打开，且程序从未写入 Gold。

## T4 · 真实运行、最少测试和交付

- [ ] 增加 `mine` 命令，同时保留 `python -m task_mining` 的 V0.1 默认预检查行为；支持单视频运行、`run_id`、输出目录和已完成阶段缓存/续跑。
- [ ] 执行一次 GX010029 **真实**端到端运行；保存调用配置（脱敏）、模型和 Prompt 版本、视频哈希、调用用量及失败日志；生成 `run_report.json`。
- [ ] 最小自动测试：旧标注隔离、未来时间泄漏、引用悬空、遮蔽与近期窗口冲突、Gold 不可自动生成、模型异常与部分失败保存；运行原有 `python -m unittest discover -v`。
- [ ] 完成 `state.md`：标明哪些是真实结果、哪些未完成；列出高优先级候选、证据路径及最重要的质量问题。

**完成条件**：单视频真实调用产出**可人工核验的候选包**。若没有任何可送审任务，属于有效的负结果，但必须如实说明为何失败、哪些证据未通过；不能称已产出高质量任务。

## 执行约束与停止条件

- **先 T0 → T1 → T2 → T3 → T4。** 如果 API 不通，提前阻断，不先写完整框架再测试。
- 每次只修阻塞当前闭环的问题；无意义的目录重构、模型横评、泛化配置、精美 UI 一律推迟。
- 全部运行产物保持 `CANDIDATE / PENDING`；正式 Gold 和四条件性能实验不在 V0.2 范围。
- 完成真实闭环并出 `review.html` 后**停止开发并请求研究者检查任务质量**；不要自动进入 V0.3。
