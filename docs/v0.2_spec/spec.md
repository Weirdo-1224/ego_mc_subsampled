# V0.2 Spec — 单视频历史依赖任务自动构造闭环

> 状态：APPROVED_FOR_IMPLEMENTATION · 版本：V0.2 · 项目：`ego_mc_subsampled`
> 开发规则：遵守仓库根目录 `AGENTS.md`；本文件只约定**研究目标、必要行为和验收标准**，具体实现优先复用已有代码。

## 1. 目标与研究边界

**本轮唯一目标**：对一个真实、无人工标注输入的 MP4，调用外部视频大模型，完成 **Raw Video → Event Discovery → Dependency Mining → Task Construction → Evidence Verification → Automatic Filtering → Human Review Package**，产生有原视频证据、可由人快速复核的历史依赖候选任务。

这是 ICME 2027 长程流式视频 Agent Benchmark 的**离线数据构造器**，不是正式被测 Agent。离线构造器可以访问全片以发现候选；但每个任务在查询时刻 `t` 的必要作答证据必须位于 `t` 及以前。旧的 `annotations/`、Legacy 转换结果、旧候选和已有 Gold **不得作为新流水线的模型输入、检索材料、答案或筛选依据**。

先使用 **GX010029** 跑通真实闭环；其它六个视频和批量任务留待 V0.3。该选择只是用于控制时长和实验成本，不使用其历史标注。

### 论文相关的能力范围

- **T1 过程状态**：当前判断依赖历史中的状态转换或过程完成情况。
- **T2 前置约束**：当前判断依赖视频中可核实的准备/前置事件或可见规则；不得凭常识虚构 SOP。
- **T3 跨窗口历史关联**：事件先后、对象连续性、跨窗口状态一致性。

任务必须**先发现依赖关系，再产生问题**；禁止先生成普通 VideoQA 后补写“历史依赖解释”。纯粹的时间距离大、只有简单历史检索价值的题目可标记为低优先级，不应假装具备复杂状态推理。

## 2. V0.2 最小工作流程

1. **视频准备**：复用 `task_mining/preflight.py` 和 `configs/datasets.json`，选择一个 `READY` 的本地 MP4；计算文件 SHA-256，获得视频时长。必要时检查所读取片段是否能解码。所有时间单位为相对视频开头的秒。
2. **事件发现**：使用一个实际可调用的视频 VLM 读取视频（全片或时间分段），输出带时间区间的可观察原子事件、对象与状态变化；区分直接观察与推断。若分段，必须还原到原始视频时间坐标。
3. **依赖挖掘（核心）**：先从事件及原视频发现跨窗口的状态转移、前置条件、对象连续性、事件顺序或“当前结果不能唯一反推历史操作”等依赖；每条依赖给出 `event_refs`、`query_time`、`history_evidence`、`dependency_explanation` 和近期窗口不足/替代证据风险的说明。后两项可作为最小扩展字段，**是待验证假设**，不是已证实结论。
4. **任务构造**：只从依赖候选生成封闭式、可客观核验的问题（优先 YES/NO/UNKNOWN），提供 `track`、`proposed_answer`、`query_time`、`current_window`、必要历史区间及 `history_mask`。不强求每个 Track 都生成题目。
5. **原视频证据复核**：通过 FFmpeg 提取相关原始视频片段，使用独立的**无前序分析上下文**的视频模型请求复核题面事实、答案支持与区间；模糊短动作允许局部增密采样。任何模型都不能用自己的前一次“文字总结”取代原始视频观察。核验结果必须是 `SUPPORTED / UNSUPPORTED / UNCERTAIN`，附具体理由。
6. **程序筛选与人工包**：先用确定性规则过滤，再根据核验结论分类 `SEND_TO_HUMAN / REJECT / NEEDS_MORE_EVIDENCE`；输出结构化文件和简洁的人工审核入口，**不得自动发布 Gold**。

> **成本控制**：先用粗粒度发现，再仅对少量优先候选进行局部视频复核；不对所有生成候选反复传整段视频。支持按阶段缓存、单视频重试与中断续跑。首次只接入**一个可用 Provider**（优先复用已有 Qwen 调用能力；若不可用可替换），不开发泛化多模型调度框架。

## 3. 核心质量门槛

每个送审候选都需要回答以下问题：

| 维度 | 必要要求 |
|---|---|
| 原始事实 | 事件/答案可追溯到可播放的 MP4 区间；不把模型猜测当作观察 |
| 时序合法 | `0 <= start <= end <= duration`；`evidence.end <= query_time`；查询窗口止于 `query_time` |
| 历史依赖 | 关键证据**位于近期窗口之前**；必须解释为什么近期画面不足以唯一确定具体答案 |
| 替代证据 | 明确检查是否还有其它历史或近期片段足以支持同一答案，无法排除则标记风险 |
| 遮蔽定义 | `history_mask` 仅作用于必要历史、不得与当前窗口相交；保持原视频时间坐标，不泄漏被遮蔽内容 |
| 可观察性 | 七段源视频已知无音轨：禁止从不可获取的音频虚构指令、说话者或语言事实 |
| 质量与多样性 | 剔除越界、无引用、证据矛盾、重复改写、明显近期可答等候选；不为数量放宽门槛 |
| 审核门禁 | 所有模型与自动程序产物保持 `maturity=CANDIDATE`、`review_status=PENDING`；`SUPPORTED` ≠ Gold |

**历史必要性不是让模型口头声称“删掉片段就答不出”。** V0.2 至少生成合法、可执行语义的关键遮蔽区间，筛查明显的近期/替代证据风险；可选对最优少量候选做独立 FULL 与 CRITICAL_MASK 预试验，**不作为交付硬门槛**。正式四条件（FULL、RECENT、CRITICAL_MASK、CONTROL_MASK）模型对照与论文统计实验留到后续版本。即使预试验通过，也不能直接判定因果必要性成立。

## 4. 输入、契约与输出

**输入**：本地真实 MP4、七视频登记配置、显式的模型配置与 API 凭据（仅环境变量或现有本地安全凭据）；**禁止**读取 `annotations/`、Legacy 转换或旧任务答案。

**接口**：保持 `task_mining/contracts.py` 中的 `VideoInput`、`EventCandidate`、`DependencyCandidate`、`TaskCandidate`、`VerificationResult`、`FilteringDecision` 及 `MiningBackend` 四个方法；必要时以**兼容的可选字段**补充依赖类型、近期不足原因、替代证据风险。为真实模型响应增加运行时解析与基础引用/时间校验；不修改旧 `benchmark/schema.json` 或 `benchmark/validate.py`。

**入口**：保留 `python -m task_mining` 现有预检查行为；新增清晰的挖掘子命令（建议 `python -m task_mining mine --video-id GX010029 --config ...`，具体参数依已有 CLI 风格确定），能在本机真实执行。

**输出**：单次运行存放于忽略 Git 的 `runs/<run_id>/`，至少包括：

- `events.jsonl`、`dependencies.jsonl`、`tasks.jsonl`
- `verifications.jsonl`、`filtering.jsonl`
- `review.html`（简洁表格 + 关键/近期片段本地播放或可打开链接）、`clips/`
- `run_report.json`（视频哈希、模型与 prompt 版本、阶段状态、实际调用数、缓存命中、错误、用量/可获得的费用、各类候选数量）

保留必要的原始模型响应供追溯，但不把密钥写入响应文件；原始 MP4 不复制、不覆盖，不提交运行结果到 Git。失败阶段保留成功阶段的真实输出，严禁用 Mock 填补真实调用结果。

## 5. 明确不做（防止过度设计）

- 不迁移旧标注和旧任务，不开发旧 Schema 的 Gold 导出适配器。
- 不支持七视频批量运行，不新增数据集，不扩展复杂标注工作台。
- 不引入多智能体编排框架、数据库、消息队列或前端工程。
- 不开发正式流式 Agent、Harness、完整四条件评测与论文可视化统计。
- 不要求每个 Track 都有候选、不为了凑数保留低质量任务。

## 6. 验收标准（以真实产物为准）

1. 在 **GX010029** 上成功完成至少一次真实视频 VLM 调用及 E2E 流程，生成上述文件；无真实 API 时如实记录 `BLOCKED`，**不能标为完成**。
2. 候选具有 **Event → Dependency → Task → Evidence** 的可追踪 ID 链；无“先提问再编造依赖”的路径。
3. 尝试挖掘约 5–10 道初始候选，**目标**筛出 2–3 道优先人工审核任务；不为凑数放宽标准。若为 0，完整流程可记为技术跑通，但**研究产出仍为 PARTIAL，不可宣称完成高质量任务构造**；应报告具体原因。
4. 人工不依赖旧标注即可打开 `review.html`，查看每道待审题的题面、答案、关键片段、近期窗口、依赖解释、核验结论和风险。
5. 完成最小的自动校验及针对禁止读取旧标注、时间越界/未来泄漏、错误引用、无效遮蔽、Gold 保护的回归测试；原有 `python -m unittest discover -v` 继续通过。
6. `run_report.json` 清楚区分 `SUCCESS / PARTIAL / BLOCKED / FAILED`，提供实际而非模拟的运行与用量记录。是否达到“高质量 Gold”只能由后续人工审定决定。

**停工规则**：只要真实单视频的候选构造与审核包已跑通、上述门槛满足，就停止扩展工程功能并交付结果，优先让研究者检查候选质量。
